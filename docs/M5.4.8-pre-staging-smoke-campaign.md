## Task 1 — `hard_resync` Forensics

### 1.1 Definición del helper

`hooks/useImmersivePlayback.ts:1110-1156` — función `hardResync(targetIndex, reason)`. Aún declarada. Cuando ejecuta:

1. Chequea `hardResyncAttemptsRef.current >= MAX_HARD_RESYNC_ATTEMPTS_PER_SESSION` → emite `PB_HARD_RESYNC_CAPPED` y `setStatus('error')`.
2. `hardResyncAttemptsRef.current++`.
3. `cancelSyncStrategy('hard_resync')` + `[HARD_RESYNC_CANCEL_EXECUTOR]` log.
4. `cancelPendingAdvance('skip_or_load')`.
5. `audioRefA/B.pause()`.
6. `dispatchMachine({ type: MA.HARD_RESYNC, targetIndex, reason })`.
7. `setStatus('paused')` + `onPlayChange(false)`.
8. Emite `PB_HARD_RESYNC` log.

## Task 4 — Memory / Cache Validation Playbook

### Procedimiento

1. Cargar Guerra (chunked, peor caso de cache) o TTS largo.
2. Activar `localStorage.setItem('immersive_debug', '1')`.
3. Reload. Confirmar `M543_BUILD_MARKER` + primer `RUNTIME_HEALTH_SNAPSHOT` baseline.
4. Iniciar playback continuo. Dejar correr 45–60 min.
5. Captura adicional cada 10 min ejecutando manualmente `__pbDiag()` y copiando el JSON.

### Métricas a registrar

| Métrica | Source | Esperado en sesión 60 min |
|---|---|---|
| `cacheEntries.audioCache` | RUNTIME_HEALTH_SNAPSHOT | Crece hasta cap (~80), después GC mantiene oscilando ≤80 |
| `cacheEntries.inFlight` | snapshot | Picos durante prefetch, vuelve a 0 entre frases |
| `activeAudioElements` | snapshot | **EXACTAMENTE 2** todo el tiempo. >2 = leak |
| `pendingTimeouts.pendingAdvance` | snapshot | `true` solo entre `sentence_advanced` y next `play_start`. `false` la mayoría del tiempo |
| `executorCancels` | snapshot | Crece +1 por cada chunk transition + cada manual nav. Tasa razonable: 1–2/min en autoplay |
| `staleCallbackRejects` | snapshot | Debería quedar en 0 durante autoplay puro. Sube solo con nav spam |
| `detachedListenersEstimate` | snapshot | **0** todo el tiempo. >0 = leak |
| `cacheMetrics.created` vs `evicted` | snapshot | `evicted` debe crecer proporcional a `created` después de minuto 5 (GC funcionando) |

### Tres preguntas operativas

**1. ¿Converge?**

Definir: tras minuto 15, las métricas oscilan en bandas estables (cache_size ±10, pending_advance toggling, etc.). Esperado = sí.

**2. ¿Crece monotónicamente?**

Definir: `audioCache` o `created` crece estrictamente durante 30+ min. Esperado = no (eviction trabaja). Si sí → leak de blobs.

**3. ¿Hay evidencia de leak?**

Indicadores:
- `activeAudioElements > 2` → leak de `<audio>` elements (probablemente reset no limpia correctamente).
- `detachedListenersEstimate > 0` → audio elements en doc sin estar en refs.
- `cacheMetrics.created` crece pero `evicted` se queda atrás → blobs no se revocan.
- `heapRatio` sube monotónicamente (vía `MEMORY_PRESSURE_WARNING`) → leak general.

## Task 5 — Layout Performance Validation Playbook

### Procedimiento

1. Smoke estándar 10-15 min en cada device.
2. Capturar TODOS los `[ACTIVE_SENTENCE_LAYOUT_PERF]` logs (típicamente 50-200 por sesión).
3. Filtrar por `tier` y `retries`.

### Métricas a calcular (post-recolección)

| Métrica | Cálculo | Target |
|---|---|---|
| **P50 layoutFitDurationMs** | mediana de todas las muestras | <10ms desktop, <30ms mobile |
| **P95 layoutFitDurationMs** | percentil 95 | <50ms desktop, <100ms mobile |
| **Worst case layoutFitDurationMs** | máximo | <200ms (cualquier device) |
| **P50 measurementDurationMs** | mediana del solo measure | <2ms desktop, <8ms mobile |
| **Retries: 0 / 1 / 2 distribution** | conteo por bucket | ≥80% en retries=0, ≤5% en retries=2 |
| **renderCount mean** | promedio | ≤1.3 (mayoría 1, algunos 2-3) |
| **settled: true %** | tasa de éxito | ≥98% (mayoría debería caber) |

### Por device

Crear bucket por device (desktop / Android / iOS) y reportar los 7 valores arriba para cada uno.

### Indicadores rojos

- P95 > target en cualquier device → optimizar fit logic o aumentar bound de retries.
- Worst case > 500ms → layout thrashing real, bug.
- `settled: false` > 5% → muchas frases overflowean. Revisar fórmula de tier reduction.
- `renderCount > 3` para algún sentence → bug del effect (no debería pasar).
