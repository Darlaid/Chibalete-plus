# M-4.2 — Playback Activation Smoke Checklist

Sprint Inmersivo V2 / Fase M-4.2 — verificación manual del lifecycle de
playback con el runtime V2 ya operativo (post `idle → opening → ready`).

**Prerequisitos**:
- M-4 cerrado (`/visor-v2-local/:id` carga, snapshot llega a `ready`).
- `localStorage.IMMERSIVE_RUNTIME === 'v2-local'` activado.
- (opcional) `window.__IMMERSIVE_V2_DEBUG__ = true` para el DevDiagnosticsPanel.
- DevTools Console abierto, sin filtros.

**Objetivo**: confirmar que play / pause / resume / goTo / closeSession
producen lifecycle observable, sin orphan audio, sin double playback, sin
callbacks stale tras `closeSession`.

## 1 · Snapshot shape extendido (M-4.2)

`runtime.getSnapshot()` debe incluir 6 campos nuevos (además de los 9 canónicos):

| Campo | Tipo | Significado |
|-------|------|-------------|
| `isPlaying` | `boolean` | shorthand de `status === 'playing'` |
| `audioState` | `'idle' \| 'playing'` | estado interno de AudioRuntime |
| `audioUrlLoaded` | `boolean` | el src del audio activo tiene URL set |
| `activeSentenceId` | `number` | alias semántico de `currentIndex` |
| `pendingTransition` | `boolean` | hay ops encoladas / procesándose en la session |
| `playbackGeneration` | `number \| null` | alias semántico de `lifecycleToken` |

Verificación rápida:
```js
const s = window.__immersiveV2Stack.runtime.getSnapshot()
Object.keys(s).sort()
// Esperado (15 keys ordenadas):
// activeSentenceId, audioState, audioUrlLoaded, contentId, currentIndex,
// isPlaying, lastError, lifecycleToken, pendingTransition,
// playbackGeneration, sessionId, status, totalIndices, userId, visualReady
```

## 2 · Logs lifecycle (intent + observación)

El viewer M-4.2 emite **dos familias** complementarias:

- **`[V2] playback.start`** — INTENCIÓN del cliente (botón presionado).
  Disparado SIEMPRE, antes del dispatch. Incluye `{ intent, sessionId, currentIndex, status, playbackGeneration }`.
- **`[V2] playback.audio.* / playback.pause / .resume / .stop / .close`** —
  EFECTO observado vía snapshot tracer (transiciones del state machine).

Esta separación permite distinguir:
- "el cliente intentó X pero el runtime no respondió" → solo intent log
- "el runtime cambió por su cuenta" (autoavance, error) → solo efecto log

### Catálogo completo

| Log | Cuándo | Disparador |
|-----|--------|-----------|
| `playback.start` | Click usuario o auto-pause de timer | viewer wrapper |
| `playback.audio.acquire.start` | Antes de play/resume | viewer wrapper |
| `playback.audio.acquire.success` | snapshot.audioState: idle → playing | snapshot tracer |
| `playback.audio.acquire.fail` | `snapshot.lastError.kind` empieza con `audio_` | snapshot tracer |
| `playback.audio.play.start` | status: ready → playing | snapshot tracer |
| `playback.audio.playing` | status: ready → playing (mismo evento, doble registro) | snapshot tracer |
| `playback.audio.ended` | status: playing → ready (autoavance) | snapshot tracer |
| `playback.audio.released` | audioState: playing → idle (sesión viva) | snapshot tracer |
| `playback.advance.next` | currentIndex cambió | snapshot tracer |
| `playback.pause` | status: playing → paused | snapshot tracer |
| `playback.resume` | status: paused → playing | snapshot tracer |
| `playback.stop` | status: * → closing | snapshot tracer |
| `playback.close` | status: * → closed | snapshot tracer |
| `playback.visualReady.true/false` | snapshot.visualReady cambió | snapshot tracer |
| `playback.{intent}.result` | Bridge promise resuelta | viewer wrapper |
| `playback.{intent}.exception` | Bridge promise rejected | viewer wrapper |

## 4 · Anti-leak verification

Tras completar S1–S9, verificar manualmente:

### 4a · No orphan audio

```js
// Debe ser 'idle' tras close + reopen
window.__immersiveV2Stack.runtime.getSnapshot().audioState
// → 'idle' o 'playing' coherente con status actual

// El runtime no debe retener audios de sesiones cerradas
const events = window.__immersiveV2Stack.diagnostics.getRecentEvents(50)
events.filter(e => e.kind === 'audio.released').length
// → debe haber ≥1 release por cada session cerrada
```

### 4b · No duplicated timers

Si el viewer agrega timers (level timer, watchdog, etc.):
- React DevTools → Profiler para confirmar que useEffects no se duplican.
- Buscar en logs `viewer.openSession.effect.start` aparecido EXACTAMENTE 1 vez
  por mount (StrictMode dance ya manejado por M-4 fix #4-5).

### 4c · No listener accumulation

```js
// El store interno mantiene un Set de listeners. Si se acumulan, leak.
// (No es directamente inspectable, pero el snapshot tracer debería emitir
// 1 log por cambio, no N.)
```

Forzar 5 cambios consecutivos:
```js
for (let i = 0; i < 5; i++) {
    await window.__immersiveV2Stack.runtime.dispatch({
        kind: 'goTo', index: i, source: 'manual'
    })
}
```

Debe haber **5** `viewer.runtime.snapshot` logs (no 25, no 50).

### 4d · No currentIndex vs visualIndex divergence

Visualmente, la sentence resaltada debe coincidir con `snapshot.currentIndex`.

```js
const s = window.__immersiveV2Stack.runtime.getSnapshot()
console.log('currentIndex:', s.currentIndex)
console.log('activeSentenceId:', s.activeSentenceId)
// activeSentenceId === currentIndex (siempre — son alias)
```

En DOM: el `<p data-testid="sentence-active">` debe tener texto =
`sentencesRef[currentIndex]`. No debe haber 2 `sentence-active`.
