## Cómo correr un smoke (workflow operativo M-5.4.2)

El runtime expone `window.__pbSmokeCapture` cuando estás en dev (`npm run dev`) o cuando seteás `localStorage.setItem('immersive_debug','1')`. El runner captura logs, snapshots, memoria y notas durante la corrida y al final emite un JSON listo para pegar acá.

**Setup previo (una vez por sesión de DevTools):**

```js
// En la console del browser, abierta sobre el visor inmersivo:
__pbSmokeCapture.start({
  smoke:     'A',                // letra del smoke A–G
  operator:  'nico',             // tu nombre/handle
  build:     '<commit SHA>',     // git rev-parse HEAD
  notes:     'Alicia, 15 min continuo, audio activo, tab visible',
  snapshotIntervalMs: 60_000,    // default. Para D (pause/resume) bajar a 5_000
});
```

**Durante la corrida:**

- Si percibís algo raro (hiccup, drift visual, glitch de audio), anotalo en vivo:
  ```js
  __pbSmokeCapture.note('minuto 7: vi un saltito visual en la frase ~40');
  ```
- Si querés un snapshot manual marcado:
  ```js
  __pbSmokeCapture.snapshot('antes_de_cambio_chunk');
  ```
- Para chequear estado parcial:
  ```js
  __pbSmokeCapture.status();
  // → { active: true, smoke: 'A', elapsedMs: ..., criticalCount: 0, ... }
  ```
- Para inspecciones puntuales (no quedan en el journal):
  ```js
  copy(JSON.stringify(__pbDiag(), null, 2));   // snapshot completo al portapapeles
  __pbMemory();                                // heap actual
  __pbWatchdog();                              // estado del watchdog
  ```

**Al finalizar:**

```js
const result = __pbSmokeCapture.stop();
copy(JSON.stringify(result, null, 2));
// → ahora tenés el JSON completo en el portapapeles. Pegalo abajo
//   en la sección "Findings registrados" como bloque ```json
```

**Reglas:**

- Una sola corrida a la vez por tab. `start()` mientras hay una activa la cancela primero (advertencia en console).
- Si cambiás de libro durante la corrida, el visor desmonta el effect y el runner se autocierra silenciosamente. El JSON parcial NO se recupera — por eso correr cada smoke en una tab dedicada y empezar después de que el libro cargue.
- Si Chrome cierra la tab, los datos se pierden. Para smokes largos (A, B), llamar `__pbSmokeCapture.snapshot('mid_session')` al menos una vez en mitad de la corrida y copiar parcial al portapapeles si querés respaldo.

**Lo que el JSON contiene** (resumen para auditoría):

| Campo | Descripción |
|---|---|
| `header` | smoke, operator, build, notes, startTime, endTime, durationMs |
| `eventCounts` | conteo por log tag durante toda la corrida (HEARTBEAT, CACHE_*, WATCHDOG_*, etc.) |
| `warningCounts.critical` / `.recoverable` | totales clasificados por severidad |
| `warningTimeline` | cada warning crítico/recoverable con timestamp y data — primeros 500 |
| `snapshots` | runtime diagnostics cada `snapshotIntervalMs` + manuales |
| `memorySnapshots` | heap + cache + executor counts |
| `notes` | texto del operador con timestamp |
| `deltas` | métricas calculadas start→end (cacheNetGrowth, heapGrowthMB, hardResyncDelta, ownershipViolationDelta, etc.) |
| `verdictHints` | flags booleanos: isOwnershipClean, isCacheStable, hasCriticalEvents, hardResyncCapBroken, heapOK, passes |

**Los `verdictHints.passes=true` NO es veredicto operacional final** — es heurística para detectar que la corrida fue limpia. El veredicto final lo dicta el operador leyendo el JSON, anotando rarezas perceptuales (audio glitches, jitter visual) que el runtime no detecta, y completando la sección "Métricas finales" abajo.

## Cómo agregar una entrada

Copiá la plantilla de la sección final y completala. NO reordenes entradas pasadas — el orden cronológico importa para auditar deriva temporal.

Campos obligatorios:

- **id** — `M54.<smoke>.<incrementor>` (ej. `M54.A.1`). Smoke = letra A–G, ALL para genéricos.
- **fecha** — ISO 8601 (`2026-05-13T18:42:00-03:00`).
- **smoke** — qué smoke estaba corriendo (A, B, C, D, E, F, G, o N/A).
- **build** — commit SHA o `working-tree` con `git status --short`.
- **observador** — quién corrió el smoke. Nombre o handle.
- **evento** — exact log tag que disparó la entrada (`WATCHDOG_STALLED_AUDIO`, `OWNERSHIP_VIOLATION`, etc.) o `manual` si lo detectó el operador.
- **clase** — EXPECTED / ACTIONABLE / NOISY / CRITICAL según `M5.4-watchdog-audit.md`.
- **condiciones** — qué se estaba haciendo. Contenido (Alicia/Guerra/otro), modo, tab visible o background, network, speed, etc.
- **reproducibilidad** — 1-shot / intermitente / consistente.
- **snapshot** — output de `window.__pbDiag()` al momento. Pegar JSON o adjuntar archivo.
- **logs relevantes** — pegar los 5–10 logs previos al evento. Filtrados, no full dump.
- **hipótesis** — qué creés que pasó. Sin certeza no pasa nada — anotalo.
- **severidad** — alta / media / baja.
- **fix aplicado** — descripción o `pendiente` o `N/A` (si EXPECTED).
- **commit del fix** — SHA cuando aplique.
